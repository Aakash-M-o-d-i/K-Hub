## 2. System Flow Diagram

Since you are integrating a **Super Admin Panel** as a gatekeeper, the flow of data is critical.

1. **React Frontend:** Captures the paper file and metadata (Year, Subject).
2. **Flask Backend:** Receives the request, saves the file to a `uploads/pending` folder, and creates a database entry with `is_approved = 0`.
3. **MySQL:** Stores the file path and user ID.
4. **Admin Panel:** Fetches all rows where `is_approved = 0`. Upon approval, the status flips to `1`, making it visible on the Landing Page.

## 3. Implementation Checklist

### **Phase 1: Database Setup (MySQL)**

Create a relational structure. For example, your `Papers` table:

* `id` (Primary Key)
* `title`, `subject_code`, `year`
* `file_url` (Path to the PDF)
* `uploader_id` (Foreign Key to Users)
* `status` (Enum: 'pending', 'approved', 'rejected')

### **Phase 2: Backend Logic (Flask)**

* Use `Flask-CORS` to allow your React frontend to talk to the backend.
* Implement a `werkzeug.utils.secure_filename` check to prevent malicious file uploads.

### **Phase 3: Frontend Dashboard (React)**

* Build the "Private Route" wrapper to ensure only logged-in students see their dashboard.
* Use `axios` for file uploads with a progress bar (since PYQs can be large PDFs).
